# Chromatic Deployment Checklist

Use this checklist when deploying Chromatic to a new server or updating an existing installation.

## Pre-Deployment

### Server Requirements

- [ ] **CPU**: 2+ cores available
- [ ] **RAM**: 2GB minimum (4GB recommended)
- [ ] **Storage**: 20GB+ free disk space
- [ ] **OS**: Linux (Ubuntu 20.04+ or Debian 11+ recommended)
- [ ] **Public IP**: Server has a public IP address
- [ ] **Docker**: Docker and Docker Compose installed
  ```bash
  docker --version  # Should be 20.10+
  docker compose version  # Compose plugin should be installed
  ```

### Domain & DNS

- [ ] **Domain registered**: e.g., `stream.yourdomain.com`
- [ ] **DNS A record**: Points to server's public IP
- [ ] **DNS propagation**: Verified with `dig stream.yourdomain.com`
- [ ] **SSL certificate**: Will be auto-generated by Caddy (Let's Encrypt)

### Network & Firewall

- [ ] **Port 80 open**: HTTP (for SSL certificate validation)
- [ ] **Port 443 open**: HTTPS
- [ ] **Port 3478 open**: TURN (UDP + TCP)
- [ ] **Port 5349 open**: TURN over TLS
- [ ] **Ports 49152-65535 open**: WebRTC media relay (UDP)

Verify with:
```bash
# From external machine
nc -zv your.server.ip 80
nc -zv your.server.ip 443
nc -zvu your.server.ip 3478
```

## Deployment Steps

### 1. Clone Repository

- [ ] Clone repository to server
  ```bash
  git clone https://github.com/davidtorcivia/chromatic.git /opt/chromatic
  cd /opt/chromatic/deployments
  ```

### 2. Generate Secrets

- [ ] Generate ADMIN_TOKEN (32+ characters)
  ```bash
  openssl rand -hex 32
  ```
- [ ] Generate TURN_SECRET (32+ characters)
  ```bash
  openssl rand -hex 32
  ```
- [ ] Store secrets securely (password manager)

### 3. Configure Environment

- [ ] Copy example environment file
  ```bash
  cp .env.example .env
  ```
- [ ] Edit `.env` with required values:
  - [ ] `ADMIN_TOKEN` - Generated admin token
  - [ ] `PUBLIC_URL` - Full URL (https://stream.yourdomain.com)
  - [ ] `TURN_SECRET` - Generated TURN secret
  - [ ] `TURN_REALM` - Your domain (stream.yourdomain.com)
  - [ ] `PUBLIC_IP` - Server's public IP address
  - [ ] `CHROMATIC_IMAGE` - Pinned image tag/digest from `ghcr.io/davidtorcivia/chromatic`
  - [ ] `PRODUCTION_MODE=true`
  - [ ] `ALLOWED_ORIGINS` - Your domain

### 4. Configure Caddy

- [ ] Edit `Caddyfile` with your domain
  ```caddy
  stream.yourdomain.com {
      reverse_proxy chromatic:3000
  }
  ```

### 5. Create Backup Directory

- [ ] Create a backup directory on the host
  ```bash
  mkdir -p /opt/chromatic/backups
  chmod 700 /opt/chromatic/backups
  ```

### 6. Deploy

- [ ] (If GHCR package is private) Login to GHCR
  ```bash
  echo "$GHCR_TOKEN" | docker login ghcr.io -u "$GHCR_USER" --password-stdin
  ```
- [ ] Pull Docker images
  ```bash
  docker compose pull
  ```
- [ ] Start services
  ```bash
  docker compose up -d
  ```
- [ ] Check all containers running
  ```bash
  docker compose ps
  # All should show "Up"
  ```

## Post-Deployment Verification

### Service Health

- [ ] **Health check endpoint**
  ```bash
  curl -s https://stream.yourdomain.com/health | jq
  # Should return {"status": "ok"}
  ```

- [ ] **Admin login works**
  1. Visit `https://stream.yourdomain.com/admin`
  2. Enter ADMIN_TOKEN
  3. Should see admin dashboard

- [ ] **SSL certificate valid**
  ```bash
  curl -vI https://stream.yourdomain.com 2>&1 | grep "SSL certificate"
  # Should show valid certificate
  ```

### TURN Server

- [ ] **Coturn container running**
  ```bash
  docker compose logs coturn | tail -20
  # Should not show errors
  ```

- [ ] **TURN connectivity test**
  1. Visit https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
  2. Add: `turn:your.server.ip:3478`
  3. Add credentials from your config
  4. Should see "relay" candidates

### Streaming Test

- [ ] **Create stream key**
  1. Admin > Stream Keys > Create
  2. Note the WHIP URL

- [ ] **Create test room**
  1. Admin > Rooms > Create Room
  2. Assign stream key
  3. Note room URL

- [ ] **OBS test stream**
  1. Configure OBS with WHIP URL
  2. Set Baseline profile, 0 B-frames
  3. Start streaming
  4. Verify "Connected" status

- [ ] **Viewer test**
  1. Open room URL in incognito window
  2. Join as viewer
  3. Verify video appears

## Security Checklist

### Credentials

- [ ] ADMIN_TOKEN is randomly generated (not default)
- [ ] TURN_SECRET is randomly generated
- [ ] `.env` file is NOT in version control
- [ ] `.env` file permissions: `chmod 600 .env`

### Network Security

- [ ] PRODUCTION_MODE is `true`
- [ ] ALLOWED_ORIGINS is configured (not `*`)
- [ ] Unnecessary ports are closed
- [ ] SSH key authentication (no password)

### Application Security

- [ ] Rate limiting is enabled (default)
- [ ] CORS is properly configured
- [ ] CSP headers are set (via Caddy)

## Monitoring Setup

### Basic Monitoring

- [ ] **Prometheus metrics accessible**
  ```bash
  curl -s https://stream.yourdomain.com/metrics | head -20
  ```

- [ ] **Log rotation configured**
  Docker handles this by default, but verify:
  ```bash
  docker info | grep "Logging Driver"
  # Should show json-file with rotation
  ```

### Alerting (Recommended)

- [ ] Set up uptime monitoring (Uptime Robot, Pingdom, etc.)
- [ ] Configure alerts for:
  - Health check failures
  - SSL certificate expiry
  - Disk space usage
  - Container restarts

- [ ] **Backup script created**
  ```bash

  chmod +x scripts/backup.sh scripts/restore.sh scripts/verify-backup.sh
  ./scripts/backup.sh /opt/chromatic/backups
  TIMESTAMP=20260206_231500
  ./scripts/verify-backup.sh "$TIMESTAMP" /opt/chromatic/backups
  # Replace with timestamp from the backup output.
  # Optional cleanup:
  ```

  ```bash
  # Add: 0 2 * * * /opt/chromatic/scripts/backup.sh
  ```

## Troubleshooting Common Issues

### Container won't start
```bash
docker compose logs <service-name>
```

### SSL certificate error
```bash
docker compose logs caddy
# Check for rate limit or DNS issues
```

### Can't connect from OBS
- Verify WHIP URL format
- Check firewall allows outbound HTTPS
- Verify stream key is valid

### No video for viewers
- Check OBS encoder settings (Baseline profile)
- Verify room is set to "Live"
- Check browser console for WebRTC errors

See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for more solutions.

## Update Procedure

When updating Chromatic:

1. [ ] Backup database
   ```bash
   docker compose exec chromatic sqlite3 /data/chromatic.db ".backup /data/backup-before-update.db"
   ```

2. [ ] Pull new images
   ```bash
   docker compose pull
   ```

3. [ ] Restart services
   ```bash
   docker compose up -d
   ```

4. [ ] Verify update
   ```bash
   docker compose logs -f chromatic
   ```

5. [ ] Run health checks (see above)

---

## Rollback Procedure

If update causes issues:

1. [ ] Stop services
   ```bash
   docker compose down
   ```

2. [ ] Restore database backup
   ```bash
   docker compose run --rm --no-deps chromatic sh -ec "cp /data/backup-before-update.db /data/chromatic.db && rm -f /data/chromatic.db-wal /data/chromatic.db-shm"
   ```

3. [ ] Use previous image version
   ```bash
   # Set CHROMATIC_IMAGE in .env to the previous pinned tag/digest, then:
   docker compose pull
   docker compose up -d
   ```
